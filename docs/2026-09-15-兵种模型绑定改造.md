# 2026-09-15 兵种模型绑定改造（去除"皮肤"概念）

## 背景

keywei 在 2026-09-14 的提交把美术提供的 4 个 GLB（`soldier01..04.glb`）做成了**玩家可选皮肤**：
部署页底部多出一行「角色形象」选择器（原型兵 + 体素兵 01–04），默认 `box`（程序化盒子兵），
选择结果存 localStorage 的 `vf_soldier_skin`，并随 PvP loadout 同步。

这不符合需求：**兵种本身就应该用美术模型**，玩家不该有第二个形象维度。

## 目标映射（美术命名顺序）

| 兵种 classId | 中文名 | GLB 文件 |
| --- | --- | --- |
| `assault` | 突击兵 | `soldier01.glb` |
| `engineer` | 机枪兵 | `soldier02.glb` |
| `support` | 支援兵 | `soldier04.glb` |
| `recon` | 侦察兵 | `soldier03.glb` |

## 改动清单

### 1. `js/soldier-voxel.js` — 皮肤 → 兵种映射表

- `SKINS`（`voxel01`~`voxel04`，与兵种解耦）→ **`CLASS_MODELS`**（`classId → { file, nameZh }`）
- `isValidSkin` → `isValidClass`；新增 `CLASS_IDS`、`isAnyReady()`
- `preload(id)` / `preloadAll()` 改为按 classId；内部缓存 `_skins/_skinPromises` → `_models/_modelPromises`
- `create(id, opts)`：入参即兵种；`classId` 非兵种 id 时回落 `opts.classId`（兼容旧调用）
- 对外仍保留 `create` / `drive` / `isReady` 三个老接口签名形态

### 2. `js/soldier.js` — 模型分发

- **删除** `getPlayerSkinId` / `setPlayerSkinId` / `SKIN_STORAGE_KEY` / `vf_soldier_skin`
- `createClassSoldier(classId, opts)`：直接 `if (SoldierVoxel.isReady(classId)) return SoldierVoxel.create(...)`；
  未就绪静默回退程序化盒子兵（加载完成重建即可自动换上）
- 新增 `opts.voxel === false` 逃生门，可强制走盒子兵（验证脚本用作对照）
- `createPreviewSoldier` 透传 `opts.voxel`，不再透传 `skinId`

### 3. `js/ui.js` — 部署页

- **删除整套皮肤 UI**：`_buildSkinGrid` / `_startSkinPreload` / `_selectSkin` / `_refreshClassStageSkin` / `_bakeSkinAvatars`
- 删除 `els.skinGrid` 注册、`openClassSelect()` 里的两处调用、`_stopClassPreviews()` 里的 `skinModels` 清理
- **新增** `_startClassModelPreload()`：调 `preloadAll()`，全部/部分就绪后 `_rebuildClassStageModels()`
  重建站台 4 个模型并重烘兵种缩略图（未就绪期间显示盒子兵占位）
- `_startClassPreviews()` / `_startLoadoutCustomizePreview()`：不再传 `skinId`
- `_bakeClassAvatars()` 逻辑不变——按 `canvas.dataset.classId` 从 `prev.models` 取模型，
  模型换掉后缩略图自动跟着变

### 4. `index.html` / `style.css`

- 删除形象选择行（`class-skin-label` + `class-skin-list#class-skin-grid`）
- 删除 `.class-skin-*` CSS 块
- 缓存令牌 `?v=voxelskin1` → **`?v=classmodel1`**（含 `style.css`）

### 5. `js/pvp.js` — 联机

- `slot.skinId` / `remoteLoadout.skinId` / `_sanitizeRemoteLoadout` 的 skin 白名单全部删除
- `_makePreviewModel(classId, team)` 去掉 `skinId` 参数；`_syncMatchPreviewModels` 的 key 去掉 skin 段
- `ensureRemoteAvatar`：就绪判定 `appliedSkinId` → **`appliedModel`**（`'glb' | 'box'`）；
  未就绪时 `V.preload(classId)`

### 6. `js/main.js` / `js/deployment-presentation.js`

- `main.js` 开赛 loadout 不再写 `skinId`
- `deployment-presentation._startSquadIntroPreview` 不再传 `skinId`；
  末尾的"皮肤就绪重建"改为"`preloadAll()` 后重建"

### 7. `scripts/check-roles.{js,html}` — 验证脚本

- `skinIds()` → `classIds()`（返回 `CLASS_IDS`）
- `render(sid)` 按 classId 渲染；传 `'box'` 时走 `voxel:false` 作为盒子兵对照
- 断言更新为 4 个兵种模型 + 对照组共 5 张截图两两不同

# 追加：动作库全量接入（同日，美术补齐 39 个动作后）

## 背景

上一节落地后动作库只有 `Walk` / `Run` / `Pick` 三个 clip，待机靠冻结 `Pick` 第 0 帧硬撑，
开火 / 蹲 / 死亡完全没有动画。美术随后在 `assets/Roles/` 放了 39 个动作，本次把它们接进游戏。

## 资产体检结论（`scripts/inspect-roles.js`）

39 个文件全部：**骨架与现有完全一致**（29 根 `Bip001` 骨骼、30fps、99 轨道），
可直接套用，无需 retarget。三个需要处理的问题：

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 每个动作文件都内嵌 1.3MB 蒙皮网格 | 无法整包进游戏 | 烘焙时按 `nodes.slice(1)` 剥掉 0 号 mesh 节点 |
| `Death` 带 1.079m、`Hit_Large` 带 0.981m 根位移 | 角色倒地时会滑出去一米 | 烘焙时压平根节点 translation |
| 495 条恒等于 rest 值的 scale 轨道 | 白占约三成体积 | 整条剥离（判据：动画常量 == 节点 rest scale） |

## 收录范围：39 → 15

只收游戏真用得上的 15 个（`scripts/bake-roles.js` 的 `ANIMS`）：

`Idle` `Walk` `Run` `Sprint` `CrouchIdle` `CrouchWalk` `JumpStart` `JumpLoop` `JumpEnd`
`Shoot` `Reload` `AimIdle` `Hit` `HitLarge` `Death`

取舍理由：

- `Pistol_*` 一只手枪系列不收——第三人称化身不区分武器，统一用步枪姿态
- `Idle`(20.5s) / `Rifle_Idle`(14s) 太长，改用 `Common_Fight_Idle`(2s) 当持枪警戒待机
- `Pick` 废弃：以前没 Idle 才拿它第 0 帧当站姿，现在有真 Idle 了
- `AnNiu` / `InHand` / `Put_Away` / `Common_Attack_*` / `Hit_Down_*` / 徒手 `Crouch_Idle`
  等玩法真用上再加一行

产物 `soldier_anims.glb` 约 **971KB**（原 217KB / 3 clip）。

## 改动清单

### `scripts/bake-roles.js`

- `ANIMS` 从 3 条扩到 15 条，新增 `loop` 字段标注是否循环
- `REQUIRED_CLIPS` 从 `['Walk','Run']` 改为 `['Idle','Walk','Run']`
- 新增 `--anims-only`：跳过蒙皮烘焙，骨架基准改从已有 `soldier01.glb` 取
  （原始 `Soldier02~04_Skin.glb` 不在目录里也能跑）
- 新增节点序列一致性校验：所有动作文件的节点名序列必须与 `ANIMS[0]` 一致，
  否则 channel 的 node 索引会串到别的骨头上
- 新增 `readFloats` / `writeFloats` / `isConstant` / `isUnitScale`
- 新增两条归一化（根位移压平、scale 轨道剥离）与对应的自检
  （自检会重读产物、确认根节点 translation 已恒定，归一化没生效就报错）
- 时间轴 accessor 按内容去重（99 条轨道共用一份 input）
- output accessor 的 `min`/`max` 删掉（可选字段，近 3000 条各带一份很占体积）
- 自检不再硬编码 clip 名单，改为 `REQUIRED_CLIPS` + 重名检查

### `js/soldier-voxel.js` — 重写驱动

- 新增 `CLIP` 常量表（15 个名字，必须与 `ANIMS[].name` 对齐）
- `REQUIRED_CLIPS` 改为 `[Idle, Walk, Run]`（原来找 `Pick`，**Pick 删掉后会导致模型
  静默回退盒子兵**——这是本次最需要先修的回归）
- `drive()` 重写为状态优先级机：`dead > 一次性动作 > 跳跃 > 蹲伏 > 站立移动`
- 新增一次性动作 `playOnce()` + 对外接口 `fire` / `reload` / `hit` / `die` / `revive` / `jump`
- `Sprint`：`speedRatio ≥ 1.05` 才播，`Run ≥ 0.85`，其余 `Walk`
- 蹲伏：读 `root.userData.crouchPose`，自己推进插值（`Soldier.updateCrouchPose`
  对骨骼角色是跳过的——它会缩放 Y 压扁骨架、改背挂枪 `rotation.x`，会毁掉推导出的四元数）
  过半算蹲、低于 0.35 算站，中间是滞回区
- 一次性动作播完用 `needResume` 标记强制切一次 locomotion
  （不 force 的话 `switchTo` 会因 `target===current` 早退，永远停在最后一帧）
- **移除启动时的 `preloadAnims()`**：动作库从 217KB 涨到 971KB，不再适合启动即拉，
  改由部署页 `preloadAll()` 与 pvp 的 `preload(classId)` 按需触发
- 移除呼吸正弦与 `BREATHE_*` 常量（有真 Idle 了）；移除 `Pick` 冻结逻辑

### `js/pvp.js` — 远端化身

- 开火：`weaponFireSeq` 变化时调 `Vox.fire(m)`（盒子兵没有 `glbAnim`，内部自动忽略）
- 阵亡 / 复活：`alive` 边沿触发 `Vox.die(m)` / `Vox.revive(m)`

### `index.html`

- 缓存令牌 `?v=classmodel1` → **`?v=anims1`**（7 处）

### `scripts/inspect-roles.js`（新增）

纯 node 无依赖的资产体检工具：扫描 `assets/Roles/*.glb`，输出骨架与
`soldier_anims.glb` 的差异、每个 clip 的时长 / 采样 / fps / 轨道数 / 是否原地 /
首尾帧差（能否循环）、是否带网格。用来判断美术新给的动作能不能接。

### 验证脚本

- `scripts/check-anims.{js,html}`（新增）：组件级。15 个 clip 逐个停在中间帧截图，
  断言名字与代码 `CLIP` 完全对齐、15 张截图两两不同；`drive()` 6 个状态 + 3 个一次性
  动作姿势互不相同；`Death` 播完必须停住不再变化
- `scripts/check-anims-e2e.js`（新增）：端到端。走完整游戏启动链，断言 15 个 action
  在运行时都在、状态机切换正确（站立→`Idle`、走→`Walk`、跑→`Run`、冲刺→`Sprint`、
  蹲站→`CrouchIdle`、蹲走→`CrouchWalk`）、开火播完回落 `Idle`、死亡是终态且不再响应开火
