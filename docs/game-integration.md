# 两种游戏模式整合

统一入口为项目根目录的 index.html。整个目录作为一个静态项目部署即可，无需运行或部署原来的 F:\codbit\voxel-frontline。

## 入口与内容

- **大型战争**：现有征服战大厅、32v32 战斗、载具、地图及编辑器，仍使用根目录 js/ 和 assets/。
- **小型战斗**：从统一首屏进入 modes/small-battle/index.html，加载后直接打开大厅。保留核心攻防、团队死斗、爆破、自由混战、枪械模式及原有 PVE/PVP 流程。
- 小型战斗大厅的“返回模式选择”回到统一首屏；对局内返回仍回到当前模式大厅。

## 结构与共享边界

两套代码源自同一底层，但玩家、武器、地图、界面和联网已有不同实现。本次在一个项目中保留两个模式运行模块，通过整页导航切换，避免同时运行两套全局 VF 对象、游戏循环和事件监听。

这次整合没有将所有同名游戏模块强制改成同一个实现。后续升级体素/物理时，需要明确两个模块的同步改造范围，或先抽取统一接口。

- js/game-entry.js：共享模式导航，兼容子目录部署和 file:// 路径。
- modes/small-battle/js/：小型战斗专属规则和运行代码。
- modes/small-battle/assets/：23 个专属或内容不同的资源。
- modes/small-battle/integration.json：共享及专属资源清单。
- 25 个内容相同的资源直接复用根目录 assets/，包括封面、字体、UI、地图数据和背景音乐。
- 两种模式共用本地 Three.js 0.160.0 包，小型战斗无需再从 CDN 下载 Three.js。联网所用 PeerJS 仍使用原有 CDN。

## 存档与联机

小型战斗的设置、经济、职业、地图、防御塔、练习成绩和局域网消息使用 vf_small_ 前缀。大型战争原有存档不变；静音偏好继续共用。

小型战斗的 PeerJS 房间前缀为 vf-small-，与大型战争分开。相同房间号码不会让两套不同的规则误连。原独立小型战斗站点的存档不会自动迁移。

外部 Kubee 宿主仍需按原来的方式提供房间与消息转发；本次浏览器验证不包含真实多人或外部宿主联调。

## 验证

- node scripts/check-game-integration.js：脚本语法、静态资源、子目录/file/embed 导航和存档/房间隔离。
- node scripts/check-startup.js http://127.0.0.1:8765/：服务启动和默认首屏。
- node scripts/check-conquest.js：现有大型战争征服规则回归。

在项目根目录启动静态服务后，访问首页即可选择两种模式。


浏览器实测：统一首屏两个入口、小型战斗自动进入大厅、五种玩法列表、返回模式选择均通过；团队死斗完成选择角色、进入 battle 阶段、生成 11 名友军 AI 和 12 名敌军 AI、返回大厅的流程，无脚本异常。未测试完整比赛结算及真实多人联机。
