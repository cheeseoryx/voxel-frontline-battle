# 统一模式大厅与部署流程

统一入口是项目根目录的 index.html。整个目录作为一个静态项目运行；无需启动原来的 F:\codbit\voxel-frontline。

## 现在的入口

首页保留“进入大厅”。点击后进入可滚动的统一模式大厅：

- 单人游戏以大型横幅展示，注明“搜打撤筹备中”，按钮进入现有单人征服人机对战。
- 大型战争、团队死斗、爆破模式、自由混战、枪械模式、核心攻防并列为六个模式卡片。
- 多人卡片直接匹配兼容房间；没有可加入的房间时创建房间。
- 右上角保留浏览服务器；列表来自平台 `rooms.list()`，支持玩法筛选和加入。
- 装备档案继续使用现有装备与士兵功能。

多人流程：模式大厅 → 快速匹配 → 装备整备 → 3 秒部署展示 → 战场。
整备期间没有强制倒计时，也没有双方准备房间。部署展示可以立即跳过，打开装备调整或武器库会暂停个人倒计时。
自由混战和枪械模式展示个人部署；团队模式展示 AI 支援编组预览，不把展示角色冒充为真实在线玩家。

## 统一界面

以原征服整备页为基础：顶部地图、模式、房间与阵营信息；左侧兵种简报；中央实时角色；底部装备栏、横向兵种卡片和部署按钮。

大型战争保留四兵种，小型模式保留原来的六兵种、武器所有权和玩法限制。枪械模式的装备仍由武器晋级规则决定。
1280×720、1440×900、800×600 的整备布局已检查，小窗口保留全部装备入口。

## 模块与资源

入口只有根目录 index.html。大厅、整备、大型战争和小型玩法都在同一文档里切换，不再跳到第二份 HTML；PlatformClient 只注入这一页。

- js/game-entry.js：封面 / 大厅 / 小型模式的页内切换，禁止 document navigation。
- js/frontline-ui.js：按当前 runtime 适配整备 UI。
- js/deployment-presentation.js：共享角色展示辅助、装备图标、小队渲染与个人倒计时。
- js/small-arenas.js：小型模式随机地图，挂到共用 VoxelWorld。
- js/zaohua-online.js：房间只走 zaohua-platform-sdk。
- styles/deployment-base.css、styles/frontline-ui.css、styles/preview-fidelity.css、styles/small-modes.css。
- modes/small-battle/js/：小型玩法规则（TDM / 爆破 / 混战 / 枪械 / 核心），不再单独开页。
- modes/small-battle/integration.json：共享和专属资源清单。

大厅、单人 Banner、模式卡片和部署页已恢复项目原背景素材。两种运行模式直接调用各自 js/soldier.js 中的原版 createPreviewSoldier；js/menu-soldier.js 不再载入。已完成的 UI 版式、队员卡片、装备栏、按钮与角色拖动交互继续保留。之前生成的素材与提示词作为历史文件保留，不参与当前页面显示。
25 个相同资源继续复用根目录 assets/，23 个专属资源留在小型模块内。两边共用本地 Three.js。联机房间只通过 zaohua-platform-sdk，PeerJS 与 Kubee iframe 通道已随文件一并删除。js/pvp.js 里那套 localStorage 旁路总线（`_busPublish` / `_ingestBus` / `_poll*Bus`）还没摘干净：它已不再驱动任何跨端同步，但仍与 `_send` 交织在 `sendBuild`、`sendWorldBreak`、`dealDamageToRemote` 等方法里空转，摘除需要单独一轮双客户端验证。

## 存档与联网边界

小型模式的本机存档仍使用 vf_small_ 前缀。大型战争存档不变，静音偏好共用。

联机容量：大型战争最多 16 名真人；小型模式房间规格仍是 2 名真人 + AI。房间目录来自平台 `rooms.list()`，没有宿主时快速匹配改为该模式的本地人机对局。

小型模式中，第二名真人整备时不占用战斗中的 AI 席位，实际部署后替换一个 AI；离开后补回。爆破模式遵守单命规则，离开后的缺员在后续回合补齐，避免回合中新增生命。

两端 AI 仍采用原有模拟方式。联机只走造化房间；没有平台宿主时快速匹配改为该模式的本地人机对局。

## 验证方法

在项目根目录启动静态服务（默认 http://127.0.0.1:8765/）后：

- node scripts/check-game-integration.js：62 个脚本语法、静态引用、白名单路由、存档和房间隔离。
- node scripts/check-startup.js：默认首页、显式大厅入口和资源 MIME 检查。
- node scripts/check-conquest.js：征服规则、阵营席位、小队与网络校验。原有“人数相等时固定加入红方”的断言已修正为对随机分队两个分支分别检查，不改变实际分队逻辑。
- node scripts/check-frontline-browser.cjs：使用 Playwright 和本机 Chrome，检查六模式部署、AI 数量、迟加入替换与离开补位、服务器浏览、装备调整暂停、自动部署、返回大厅和窗口尺寸。测试截图默认写入 tmp/frontline-ui-check，可用 VF_UI_OUTPUT 更改目录。

- node scripts/check-preview-fidelity.cjs：检查 800–2705 像素宽度下的装备与部署布局、档案页导航避让、角色拖动旋转、兵种展示与玩家卡片排序；实机截图保存在 docs/ui-refactor/。

浏览器测试需要可用的 playwright 模块。当前工作环境可通过 NODE_PATH 指向已配置的 Codex Node 依赖目录后运行，无需向游戏添加运行依赖。

已知既有资源问题：音频模块尝试读取不存在的 assets/music/theme.mp3；项目内存在 theme.wav。浏览器检查单独记录这一既有 404，其他资源缺失会导致检查失败。

预览还原复测：六模式完整流程曾通过；后续连续复测在切换回大厅时出现一次 60 秒加载超时，独立运行大厅、大战场部署和小型模式返回大厅均通过，未捕获独立复查中的页面错误。该偶发超时尚未定位，不能据此认定已解决。多尺寸界面检查与角色旋转检查通过。

团队部署 UI 对齐：styles/squad-ui.css 仅作用于小队部署层。顶部拆分编组摘要与倒计时；队员卡片采用姓名、兵种图标、定位、三格装备结构；底部将装备栏与双操作按钮分组，并适配 2705×1623 至 800×600。角色模型、背景素材、展示镜头及画布区域未在本轮修改。

## 入口与跨模式切换修复

封面的“进入大厅”由共享入口捕获，始终打开模式列表；旧小型模块封面只返回统一大厅，模式选择必须来自明确的模式卡片。加入同位置连续点击保护并更新入口脚本缓存版本。新开页面中的单击误入独立作战尚未复现，因此不将旧缓存或连击认定为唯一原因。

启动在页面解析完成后安排，并具有不依赖绘帧的定时回退。小型模式的地图对象采用延迟生成，仅在取得匹配种子后构建所选地图，去除默认城市与地图工具的重复初始化。整备和大厅期间停止无用场景渲染；退出小型对局在同一文档内拆掉规则并回到统一大厅，不跳另一份 HTML。

验证：scripts/check-mode-navigation.cjs 禁用所有外部 HTTP 脚本，设置旧 FFA 模式记忆，连续在同一标签页测试五种模式的进入、取消、开局、退出和席位清理；同时检查禁用 requestAnimationFrame 回调仍能启动大厅。实测进入整备约 1.2–2.5 秒，退出约 2.3–2.6 秒，运行期间无页面错误。此前完整六模式与双页面迟加入/离开补位检查也通过。

首次进入首页：旧的 screen=modes 地址参数不再直接打开大厅。仅对局内返回时写入短期、一次性的当前标签页返回状态；到达主项目后立即消费该状态并清除地址参数。直接打开旧地址或刷新页面均显示首页，点击“进入大厅”后展示模式列表。浏览器回归覆盖旧地址、模式记忆、五模式返回大厅以及返回后的刷新。
