## 二、代码分层（改动落点）

### 1. 资产层 —— `scripts/bake-roles.js`（307 行，新增）

- 输入 `assets/Roles/`（**被 .gitignore 排除的原始 UE5/Mixamo 导出，不入库**）
- 输出 `assets/characters/soldier01..04.glb`（贴图统一降到 1024²）+ `soldier_anims.glb`（仅骨架 + Walk/Run/Pick）
- 44MB → 约 6MB；先写 `.tmp`、自检通过才 rename，避免产出半成品
- 依赖 python + Pillow 做贴图重采样，缺失时明确报错中止
- 四个角色共用同一副 **Bip001 骨架**，动作按节点名寻址，直接套用，**无 retarget**

### 2. 运行时层 —— `js/soldier-voxel.js`（308 行，新增）

对外接口 `VF.SoldierVoxel`：

| 接口 | 作用 |
|---|---|
| `SKINS` | 4 个皮肤元数据（voxel01–04 / 体素兵 01–04） |
| `preload(id)` / `preloadAll()` | 懒加载，含动作库；失败态也缓存 |
| `isReady(id)` | 皮肤 + 动作库都就绪才算 |
| `create(id, {classId, team})` | `SkeletonUtils.clone` 出骨骼角色 |
| `drive(root, dt, state)` | 由 `VF.Soldier.updateLocomotion` 委托 |

关键约定：

- 模型原生朝 +Z，与盒子兵一致 → 外层 `wrap.rotation.y = π`（`SoldierFacing`）
- 待机 = **Pick 第 0 帧冻结**（绑定姿势是 A-pose 摊手，不可用）
- 呼吸 = `mixer.update` **之后**给 `Bip001-Spine1` 叠极慢正弦（0.25Hz / 0.015rad），顺序写反会被 clip 采样覆盖
- 走/跑切换 `RUN_THRESHOLD=0.85` + **120ms 滞回**，防边界每帧互切
- 武器：`Dummy001` 挂点背枪，用 `Soldier.buildGunProp('rifle', -0.85)`；朝向用 socket 世界四元数求逆推导
- `frustumCulled = false`：蒙皮后包围盒失效，否则会闪没
- 启动时只预载动作库（217KB），皮肤按需加载

### 3. 分发层 —— `js/soldier.js`

- `getPlayerSkinId()` / `setPlayerSkinId()`：localStorage key `vf_soldier_skin`，默认 `'box'`（原型兵）
- `createClassSoldier(classId, {skinId})`：**非 box 且 `isReady` 就走体素分支**，创建失败静默回落盒子兵
- `updateLocomotion()`：开头判断 `root.userData.glbAnim` → 直接委托 `SoldierVoxel.drive` 并 return。注释强调**必须分支在 `initLocomotion` 之前**，否则盒子兵的腿部摆动逻辑会找到背挂的 Weapon 和 mixer 抢变换
- `updateCrouchPose()`：`if (root.userData.glbAnim) return;` —— 体素骨架无蹲伏 clip，Y 缩放 + `gun.rotation.x` 写入会压扁骨架并摧毁背挂枪的推导四元数
- `buildGunProp(style, muzzleZ)`：从 `addGun` 里抽出公共枪体构建，供体素角色复用作背枪
- `createPreviewSoldier` 透传 `skinId`

## 三、设计决策提炼

1. **不 retarget**：四个角色骨架同名同构，动作直接套。代价是新增角色必须同骨架。
2. **盒子兵与体素兵走同一入口**：`createClassSoldier` 内部分发 + 失败静默回落，所有调用点只多传一个 `skinId`。
3. **动画缺失是资产限制不是取舍**：只有 Walk(1.2s)/Run(0.8s)/Pick(1.6s)，开火/蹲伏/死亡无动作，当前**不做任何动画响应**。
4. **原始资产不入库**：只有烘焙产物进 `assets/characters/`，`assets/Roles/` 被忽略。

## 四、遗留风险（值得跟 keywei 确认）

1. **蹲下无视觉表现**：`updateCrouchPose` 对体素角色直接 return，蹲伏时模型高度不压低 —— 需确认**碰撞体/命中判定是否也跟着不变**，否则会出现"看着站着其实蹲着"的不一致。
2. **烘焙不可重现**：`assets/Roles/` 被 gitignore，别人拉仓库跑不了 `bake-roles.js`，只能依赖已提交的产物；建议补一份原始资产的获取方式（或把源 GLB 传到网盘并在文档注明）。
3. **皮肤缓存无上限**：`_skins` / `skinModels` 只增不减，4 个皮肤 + 展示位模型常驻显存，量小尚可，后续加皮肤需评估。
4. **远端化身换肤时机**：依赖下一帧 `ensureRemoteAvatar` 被调用才替换，若该帧不调用（如静止未更新）会短暂停留在盒子兵。
5. **无开火/受击/死亡动画**：PvP 里体素角色的战斗反馈会比盒子兵弱，是可见的表现缺口。
