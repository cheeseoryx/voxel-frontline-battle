# 开发计划、需求清单与验收

## 1. 实施策略

全范围按“先验证一局好玩，再扩大内容”推进。P0为当前里程碑不可缺项；P1为正式版必须具备但可以晚于闭环；不把正式版内容称为可以永远省略的可选项。

规划假设：3名程序（系统/AI/引擎可兼任）、1名策划兼关卡、1名美术，另有UI/音频/QA支持。现有素材和战斗代码可复用是前提；具体投入须在M0依赖审计与性能基线后重新估计。文中的人日为粗估工作量，不是固定报价，也不等同多人并行后的日历工期。

- M0 范围和引擎基线：1–2周。退出条件是复用边界、坐标比例、性能测量和配置入口明确。
- M1 最小闭环：3–4周。能够带普通装备进图、搜刮、交战、拿目标、撤离/死亡、结算/恢复。
- M2 垂直切片：5–6周。一张地图达到目标体验，破坏与任务物不冲突，10人试玩通过。
- M3 正式内容：8–10周。扩充三图、12枪、96物品、合同/事件/首领，以及预算内结构坍塌。
- M4 稳定与平衡：4–6周。完成存档故障注入、种子、性能、旧模式回归和离线发布检查。

阶段顺序预算21–28周，另预留20%返工缓冲，约25–34周。只有切片达标才进入内容扩充。若M0发现必须重建碰撞/导航或结构物理，单列技术项目与新增工期，不能假定包含在既有系统里。

## 2. 可砍与不可砍

资源紧张时首先减少地图数量、普通AI类型、首领和局内事件种类；其次减少枪械类型。保持物品和地图数量的文档/配置同步，不用换皮数量掩盖缺内容。

不可为了赶工删掉：完整成功/失败结算、品质一致性、主目标/出口可达、暂停一致性、物品原子转移、当前局恢复、首页正确入口、旧模式隔离。这些决定一局能否可靠完成。

不重新引入长期养成来弥补地图不足。若重玩动力不够，优先改善路径、目标组合、敌人配合和风险收益。

## 4. 发布必须满足的用例

- **T01 首次启动**：没有活动局，打开首页。预期：只显示首页，点大厅再点单人后才进入整备。
- **T02 旧地址**：用遗留大厅/模式参数打开根入口。预期：不能自动开局，恢复只能由单人入口主动选择。
- **T03 纯单人**：完整进入一局。预期：没有Peer房间、真人补位、友军小队或旧模式经济写入。
- **T04 初装一致**：三方案分别进入新局。预期：全部Q1，背包5/12，已装填弹药不算进备弹。
- **T05 品质数值**：同枪依次使用四品质打同一目标。预期：只有定义的系数变化；无随机词条与配件。
- **T06 低品质可用**：Q1完成每张图任一主合同。预期：存在无需高品质强制门槛的通关路径。
- **T07 头身护甲**：同枪命中头部与身体。预期：分别读取头盔/护甲，减伤不重复套两次。
- **T08 换弹取消**：在提交点前换枪，提交点后再换枪。预期：各路径弹药总数守恒，不复制/吞弹。
- **T09 背包溢出**：满大背包换小背包、全拿超量物资。预期：显示明确原因，物品留原处或按确认放地面。
- **T10 唯一所有权**：连续拾取/丢弃/换装/恢复。预期：任何instanceId只出现在一个拥有者。
- **T11 消耗打断**：治疗读条中射击、受伤、移动。预期：效果与扣除同时取消；完成时才消耗。
- **T12 开箱重载**：开箱记录内容，退出恢复再查看。预期：同实例同品质，已取物不重生。
- **T13 破坏开箱**：先炸箱再搜索。预期：仅原物品释放，不额外生成一套。
- **T14 关键物落空**：打塌任务物下方地板。预期：物品进入附近有效锚点且可完成合同。
- **T15 路被拆毁**：破坏目标区主要桥或阶梯。预期：存在免费绕行/清理路径，不永久软锁。
- **T16 AI视线**：进房关隔墙或投烟转向离开。预期：敌人转为最后位置搜索，不持续实时透视追射。
- **T17 援军预算**：让指挥员多次呼叫并重载。预期：整图增援不超过8，事件额外敌人不超过2。
- **T18 几何导航**：玩家打出通道或打掉AI脚下地板。预期：碰撞、AI路径和地面状态一致。
- **T19 暂停一致**：交火中Esc并等待60秒，再切出应用。预期：时间、伤害、弹道、读条和AI全部冻结。
- **T20 撤离条件**：分别进入E0/E1/E2。预期：条件和等待时间可见，电池仅有效激活时扣一次。
- **T21 撤离边界**：读条末尾受伤、死亡、出圈、超时。预期：受伤不重置，死亡/超时优先，出圈重置。
- **T22 提前撤离**：不拿主目标仅带贵重品离开。预期：撤离成功/主目标未完成，最高B，不称为成功主合同。
- **T23 计分封顶**：超量贵重品、击杀和探索。预期：分项封顶，总分≤10000，不因重复事件上涨。
- **T24 新局重置**：Q4满装成功后再来一局。预期：新runId和seed，装备Q1，无货币仓库经验。
- **T25 关闭恢复**：活动局不同阶段关闭窗口后继续。预期：恢复同一局最近快照，不重抽也不产生跨局装备。
- **T26 终局幂等**：结算提交中断、重开两次。预期：同runId仅一个结果，不能重新转为活动局。
- **T27 坏档/配额**：注入错误版本/写入失败/配额不足。预期：保留有效快照，提示可重试，不静默吞掉存档。
- **T28 双页竞争**：两标签打开同一活动局。预期：最多一个写入者，另一页不继续推进库存。
- **T29 界面尺寸**：全部规定分辨率逐页操作。预期：顶部/底部无遮挡，滚动区域与焦点正确。
- **T30 资源回收**：连续20局进退、50次暂停恢复。预期：无监听器叠加、残留音效和单调内存增长。
- **T31 断网**：阻断所有外部网络后启动完成一局。预期：游戏逻辑与必需资源完整，无网络库阻塞。
- **T32 旧模式回归**：大征服及五种小型模式进出。预期：原来入口、装备、UI、角色、背景和联机行为不被搜打撤修改。

## 5. 自动化与人工验证分工

自动化：配置引用/数量/权重/容量、伤害公式、库存守恒、种子重放、结算幂等、存档迁移、状态机边界、1000种子图可达性。生成器检查只能证明生成数据约束；场景碰撞可达性必须在实际地图构建后运行。

人工：敌人预警是否公平、地图是否易迷路、搜索是否冗长、武器手感差异、品质辨识、音效层次、是否出现“继续搜还是撤”的真实选择、全部UI尺寸。

当前文档包附带的validate-design.cjs仅检查策划数据，不冒充游戏测试。游戏尚未实现的验收用例应保持未通过状态。

## 6. 试玩记录与调整顺序

切片至少10名目标玩家，各3局；记录完成主合同率、成功撤离率、首次发现Q2时间、背包满载时间、死亡原因、总交战次数、脱战成功次数、放弃物资原因与实际路线。原始记录仅存本地开发环境，不默认建设云数据系统。

先改可读性和可达性，再改敌人密度/视听，再改补给，再改品质数值。不能用全图药品翻倍掩盖隔墙瞄准，用更高枪伤掩盖不合理出生，或用奖励解锁弥补无聊路线。

每轮锁定configVersion。至少保留3个可重放种子：低资源保守路线、标准任务路线、最重破坏路线。平衡结论要有版本号与录像，不能只写“感觉变好”。

## 7. 美术与音频交付清单

模型：复用并校对12套枪、3类防具/背包基础表现、原角色；品质使用统一标记，不复制48套高模。
图标：至少96个可辨识定义映射；同枪可共享基础图标再叠品质框，需验证最终显示结果而不是强行产出96张独立图。
场景：三地图地标套件、可破坏材料块、六类容器、三种撤离标识、终端/合同物、桥板与通行门。
特效：枪口/命中/材质破损、破片、烟雾、闪光、诱饵、有限结构坍塌、合同物恢复提示。
音频：各枪开火换弹、不同材质脚步/破坏、AI怀疑/发现/呼叫/换弹预警、物品拾取、条件不满足、撤离读条/成功/失败、暂停恢复。
UI：7个页面/层，全部空态/加载/失败/禁用/暂停/焦点状态完整；不新增人物背景资产。
