# 界面交互与工程落地需求

## 1. 现有项目接入依据

本次实际检查到：
- js/ui.js 的 solo 分支目前调用 VF.startConquest32；因此当前单人 Banner 仍进入原有人机征服，不是已经完成的搜打撤。
- js/economy.js 使用 vf_meta_v1 保存前线币、商品和备战资源，不能用于本模式的战利品。
- js/arsenal.js 是现有装备选择/展示系统，包含主要武器、副武器、工具、投掷物等槽位，可参考布局，但“已拥有武器”和长期购买逻辑不能继承。
- js/skills.js 包含兵种技能、回血和冲刺等能力，需要在新模式隔离。
- js/weapon-catalog.js 已定义伤害、射速、散布/精准、后坐、弹匣和换弹等字段，是武器表现复用的候选。
- js/voxel-world.js 具有世界和物件破坏相关实现；尚未通过本轮工作验证其支撑坍塌、移动碎块、寻路更新和任务物恢复能力。
- 两种现有运行模块通过整页切换隔离全局状态；新模式应沿用清晰的运行边界。

上述是定点代码检查，不是完整引擎审计。开发第一阶段必须列出实际调用依赖，避免把“文件名存在”误判为“功能已满足”。

## 2. 产品入口

首页默认可见 → 进入大厅 → 单人搜打撤 Banner → 单局整备。

Banner 展示：单人PVE / 单局15–25分钟 / 局内装备品质 / 搜索·战斗·撤离。删除“筹备中”仅在本模式达到上线门槛之后；开发期间用功能开关隐藏未完成入口。

浏览服务器与其他六种玩法保留。点击本模式不调用 quickMatch、createRoom、Pvp.init 或队伍部署补位。

新模式的旧局恢复：
- 没有活动局：打开整备。
- 有活动局：显示“继续上次对局”“放弃并开始新局”。
- 旧局已结束但未离开结算：打开那一局的结算，不自动开新局。
- 首次打开整个游戏仍显示首页，不根据活动局或URL自动跳过首页；恢复选择在主动点击单人Banner之后出现。

## 3. S01 单局整备

沿用现有整备页的顶部/中央角色/底部操作区，不换角色模型和背景图。

顶部：模式名、所选地图、预计局长、标准/挑战。
左侧：三种基础装备方案，列出主副武器、弹种和初始医疗；所有方案同为普通品质。
中央：原角色展示，允许现有旋转交互；不展示四人队列。
右侧：六处地标小地图、合同类型说明、三个撤离点条件。
底部：本局装备一览、开始行动、返回模式大厅。

按钮：
- 切地图：更换场景简介和出战信息，不扣资源。
- 切方案：更换当前显示装备，不进入武器商店或改装页。
- 开始行动：冻结本局配置→预生成种子和合同→写入活动局→加载。
- 返回：关闭本页，不触发开局或保存虚假的活动局。

错误状态：资源加载失败提供重试/返回；保存失败不能在无可靠对局记录时偷偷开局。再次点击开始不生成第二个runId。

## 4. S02 加载与落地

加载阶段显示地图名、主合同简介、一个撤离提示，以及有真实阶段依据的“准备地图/布置目标/加载角色”。没有精确进度则显示阶段文字，不伪造百分比。

只有完成碰撞、目标、敌人安全区和存档初始化后才开放输入并开始25分钟计时。落地前的倒计时不计入局时。

保留“取消加载”操作：取消令牌失效，释放已创建场景、标记run aborted_before_start，回整备。完成回调不能在取消之后再打开游戏。

## 5. S03 局内HUD

左上：主合同两行摘要、三个委托折叠列表。
上中：指南针和玩家放置的一个导航标记；未发现敌人不显示穿墙轮廓。
右上：剩余时间；不足5分钟/1分钟提供文字和轻提示音，不连续闪烁遮挡。
左下：生命、体力、带秒数的负面状态。
右下：手持武器名称、品质名称+标记、弹匣/备弹、四个快捷消耗品。
交互点：物品名称、品质、占用、简短替换差异、E操作；交互读条在同一位置。
背包按钮附近：容量使用与携带价值，例如“9/16 · 待带出价值1450”。

默认键位在本模式单独定义，避免与当前兵种技能冲突：
- WASD移动、鼠标瞄准/射击、Shift冲刺、Ctrl蹲下、Space跳跃、R换弹。
- 1主武器、2副武器；3–6快捷消耗品；G投掷当前选定投掷物。
- E交互、Tab背包、M地图、Esc暂停。背包中拖入快捷位可绑定。
- 按住交互完成后触发一次；关闭界面时必须释放鼠标锁状态，返回后用户点击场景恢复锁定。
- 全部键位可改；冲突检查、恢复默认和按住/切换蹲下选项必须可用。

## 6. S04 搜索与背包

两栏：左侧容器/地面列表，右侧当前装备和背包；下方固定“容量、待带出价值、关闭”。容量列表采用固定行高，不做格子拼图拖动。

默认行为：
- 单击选中显示详情，双击只对装备执行“尝试装备”；普通物品不双击消耗。
- 明确“拿取”“全部拿取”“替换装备”“丢弃”“使用”按钮；全部拿取按现有排序填到容量上限，剩余物品留在来源并提示未拿数量。
- 拖拽可作为增强操作，所有功能都有按钮替代。
- 丢弃合同物需提示位置会留在地面，仍可拾回；不能删除。
- 替换已装备主武器时，旧武器只有在背包能装下时入包，否则明确提示将放在脚边并允许取消。
- 可按类型/品质/价值排序；显示任务物标记，未知价值不存在，需要玩家比较的是空间和风险。

枪械面板只显示基础属性和品质后的实际值。不保留“配件”“枪匠”“升级”“维修”页签。相同武器不同品质比较时，只有受品质影响的四个指标显示变化。

容量不足时禁止静默截断武器弹匣；快捷道具被消耗或丢弃后绑定自动变空，不指向另一件未经选择的物品。

## 7. S05 地图与撤离

地图显示：当前玩家、已探索地标、目标区域、所有撤离点及条件、已发现通路。尚未发现的容器不全部透视显示。

撤离点四态：可用、尚未开放、等待接应、需要电池。点击显示剩余开启时间、读条时长与路线标记；不会开始瞬移或自动寻路控制玩家。

站进区域即显示撤离读条、带出的主目标状态；读条期间仍可移动/射击，走出区域重置并说明原因。最后1秒不播放遮挡视线的全屏动画。成功锁定结果后再淡出场景。

## 8. S06 暂停/保存退出

四个操作：继续、设置、保存并退出、放弃本局。设置不恢复游戏模拟。切出应用自动暂停并显示原因。

保存并退出先显示“正在保存本局”，成功后才卸载；失败时保留暂停状态并提供重试。放弃本局提示“本局装备和目标将清除，下一局仍从普通装备开始”，确认后写终局，不直接删数据库。

这是有损放弃的产品确认，不是每次普通返回都加确认。界面其他操作不要频繁弹框。

## 9. S07 结算

上方：生存结果、主目标结果、标准/挑战、地图和本局用时。
中间：最终评级与分数分解，携带物价值上限扣除清楚可见；死亡显示未带出价值，不把它当余额。
下方：本局三件关键收获/事件、再来一局、返回模式大厅。

文案必须说明“本局结束，装备不带入下一局”。不出现“存入仓库”“出售”“升级”“解锁”“奖励领取”“经验+”等长期暗示。

再来一局回整备，保留地图/难度/方案这些偏好；新runId、新seed、普通品质初装。按钮不直接复用死亡场景。

## 10. UI验收尺寸与可访问性

至少验证800×600、1280×720、1440×900、1920×1080、2705×1623。内容放不下时中间列表可滚动，顶部摘要与底部主操作保持可见，禁止整页底部按钮被裁切。

品质色之外同时提供名称、Roman标记、可读对比值；允许关闭强闪光、震屏、动态模糊和压制特效。敌人预警同时用动画/音效与可选字幕，不能只依赖颜色或音效之一。

输入界面有焦点时不触发射击、换弹或丢弃；打开/关闭连续20次不积累监听器，不使鼠标锁失效。

## 11. 推荐代码边界

新增独立入口 modes/extraction/index.html 与 modes/extraction/js/。继续复用根目录素材；只加载一份THREE和一套本局世界，不把大征服与小型战斗的main同时引入。

建议模块（为新增规划，不表示文件已存在）：
- run-controller：状态机、计时、runId、暂停、终局。
- mode-rules：封装物理尺度、伤害、品质、AI与掉落配置。
- run-inventory：物品实例、容量、装填与快捷引用。
- loot-service：种子、容器、敌人库存、一次性掉落。
- contract-service：目标事件、主物品与委托条件。
- extraction-service：开放条件、呼叫、读条。
- encounter-director：敌人生成、警戒、事件预算。
- destruction-adapter：破坏事件、碰撞/导航失效、关键物救援。
- run-storage：原子快照、恢复、迁移、写入所有权。
- extraction-ui：整备/HUD/背包/地图/结算和输入隔离。

复用方式：射击表现、声音、角色和材质通过适配层接入；所有本模式数值从独立mode-rules输入，不直接改旧模式的全局伤害。旧经济、兵种技能、团队复活和PVP快速匹配不得作为bootstrap依赖。

路由白名单增加extraction，首次无明确继续意图时只显示整备，不从任意URL query自动部署。旧模式从新模式返回后仍遵守首页/模式大厅入口约定。

## 12. 数据与事件契约

ItemDefinition：固定ID、分类、基础类型、品质、占用、堆叠上限、属性、产出类型、计分值。
ItemInstance：instanceId、definitionId、ownerRef、quantity、loadedAmmo(仅枪)、position(仅地面)、spawnId；品质来自definition，禁止实例再附加随机词条。
RunState：schemaVersion、runId、seed、configVersion、state、simTime、mapId、difficulty、player、inventories、enemies、containers、contracts、extracts、events、destructionDeltas、revision。
RunResult：runId、survivalOutcome、mainComplete、scoreBreakdown、finalScore、rank、completedAtSimTime。

统一事件：
- ItemTransferred：来源/目标/数量/actionId。
- DamageApplied：来源、目标、实际伤害、命中部位。
- ContainerRevealed：containerId、固定物品实例集合。
- ContractProgressed：contractId、objectiveId、唯一触发对象ID。
- GeometryChanged：bounds、supportGroup、navRevision。
- ExtractionFinished：runId、extractId。
- RunResolved：runId、唯一结果。
- StorageFailed：操作阶段、可恢复原因；不包括无关隐私数据。

事件必须幂等。分数从最终状态计算，不从UI按钮点击累计；战利品价值只统计当前实际持有的可计分实例，不能把已经丢出的物品计入。

## 13. 保存方案

使用独立 IndexedDB 数据库 vf_extraction_v1，不写入 vf_meta_v1，不触碰现有小型模式存档。objects至少包括runs、snapshots、results、settings。

出战、拾取/消耗、目标获取、撤离、放弃是关键事务；常规移动/AI/地图差量每15秒原子快照。事务中同时保存状态与对应revision，不能先删除旧记录再在另一个事务写新记录。[IndexedDB事务说明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)

结算事务同时写终局和结果，runId作唯一键；事务未提交时界面显示待保存，不发出第二次结果。存档成功在事务complete后确认，不能只依赖某一条put成功。[IDBTransaction](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction)

浏览器可能清理站点数据或遇到配额限制；支持导出/导入当前局快照、校验版本和校验和。申请持久存储失败不伪称有云备份。导入前展示将替换当前局，损坏/版本不支持则拒绝覆盖有效快照。[浏览器存储限制](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

多标签页同一活动局只允许一位写入者：事务内验证ownerId和递增revision；第二页只读并提示返回首页。失去写入所有权的旧页暂停，不能继续保存。是否支持自动接管属于实现选项，但同一时刻双写绝不可接受。

## 14. 性能与资源生命周期

正式目标：选定并记录一台项目基准PC，1080p标准画质下稳定60fps，最重允许场景的帧时间P95≤25ms；低画质最低30fps。这里只是验收目标，未经引擎基准不能宣称达到。

建议初始预算：AI逻辑2ms/帧、局部几何更新3ms/帧；常态不产生>100ms主线程任务；碎块/掉落渲染合批；远处AI低频逻辑但保持状态确定。距离分层不能让未激活AI直接打伤玩家。

爆炸批处理、碰撞更新、导航局部失效和物品恢复必须同一事件链完成。导航未恢复时角色停留在最后有效位置；不能继续走旧路径穿过新墙或悬空地板。

退出顺序：禁止新命令→写入终局/快照→取消任务和计时器→停止模拟→解绑输入/事件→释放本局GPU对象和碰撞数据→导航。保留共享只读素材缓存时采用引用计数，不能提前释放其他页面需要的资源。

验收：连续20次进入/退出后内存无单调增长；同一局暂停/恢复50次模拟不重复；断网可完成整局；旧的网页无法往新局发送有效回调。
